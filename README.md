# 锁单 · 时间锁

一个跑在浏览器里的**时间锁密码箱**：把一串密码锁到你指定的日期，到期之前任何人——包括这个应用本身——都拿不到明文。它使用 [drand](https://drand.love) 公共随机信标做时间锁加密，不需要账号、服务器或数据库。

> 这不是交易插件，也不接触任何券商账户。它不能阻止你打开交易软件、手动平仓或卸载它；它只保证在到期之前，那串密码不以明文形式存在于任何地方。

## 在线使用

公网地址（已部署到 GitHub Pages，绑定 `c17323.top`）：

**https://c17323.top/trade-lock/**

把这个链接发给别人，对方就能在自己的手机/电脑上打开。每个人的锁都只存在各自浏览器的 `localStorage` 里，互相看不到，也不会上传到服务器。仓库源码在 [c17323/trade-lock](https://github.com/c17323/trade-lock)。

## 它解决什么问题

“拿不住单”通常不是不知道该怎么做，而是盘中忍不住动手。把**执行权**从当时的自己手里拿走，比事后复盘更有效。这个工具的做法是：

1. 页面在本地生成一串高强度随机密码；
2. 用未来才会生成的 drand 随机信标把它加密；
3. 明文立即从内存和输入框清除；
4. 到期后，页面获取对应轮次的信标并解密。

在到期之前，解密所需的密钥（信标签名）还没有被网络生成出来，所以没有“后台密码”“管理员后门”可以提前打开。即使删除应用或清空浏览器数据，也只会丢失密文，不会提前得到密码。

## 快速开始

```bash
npm install
npm run build
npm run serve
```

打开 http://localhost:4173 。

生产环境只需要静态托管以下文件：

```
index.html
app.js        # npm run build 生成
styles.css
manifest.webmanifest

```

可以放到 GitHub Pages、Cloudflare Pages、Netlify Drop 或任意 HTTPS 静态空间。**必须用 HTTPS**，否则浏览器不会注册 Service Worker，PWA 也无法添加到桌面（核心加密功能仍可用，但不建议）。

## 鸿蒙上怎么用

1. 把上面的静态文件部署到 HTTPS 地址；
2. 在华为浏览器打开该地址；
3. 菜单 → **添加到桌面**（或“添加到主屏幕”）；
4. 之后从桌面图标打开，效果接近原生应用。

纯血鸿蒙 NEXT / HarmonyOS 5 及以上使用 ArkWeb 内核，能正常运行本页面；鸿蒙 4.x 同样可用。它不是 `.hap` 原生应用，不需要侧载，也不依赖安卓兼容层。

## 分享给别人

直接发公网链接即可，对方不需要账号：

- 每个人生成的密文只存在**自己的浏览器**里，互相看不到；
- 不要多人共用同一份备份文件，也不要把同一个密码锁给多个人；
- 页面是公开的静态页，任何人都能打开，所以不要在页面里填助记词、私钥或别人的密码。

## 建议的使用方式

先用 1 分钟后的时间测试一遍完整流程，再用于真实日期。

比较稳妥的“锁单”流程（以需要登录密码的交易账户为例）：

1. 在页面里生成密码，把解锁时间设到你计划的最小持仓周期；
2. 立刻导出备份，放到另一台设备或网盘；
3. 到券商/交易软件里把登录密码改成这串密码，关闭指纹/面容登录和“记住密码”；
4. 退出登录，手机上只保留查询密码或只读密码；
5. 到期后回到页面解密，再把密码改回去。

**先确认你的券商允许修改密码、且不会因为异地/多次尝试触发风控。** 不同券商规则差异很大，操作前先读清楚。

## 硬限制（请务必读）

- **不能阻止交易**：它不监听、不拦截、不注入任何交易软件。你仍然可以换设备、用网页版、找客服重置密码。
- **不能防卸载**：普通鸿蒙应用没有“禁止卸载”权限。这里做到的只是“卸载也不会提前解锁”，而不是“卸载不了”。
- **丢失即永久丢失**：明文不保存。清空浏览器数据又没有备份，密码就真的没了，没有找回入口。
- **到期需要联网**：解密时要向 drand 获取对应轮次的信标；没网就只能等有网。
- **不要放助记词/私钥/唯一救命密码**：这类东西丢了无法重置，风险远高于“拿不住单”。
- **不要用它锁住唯一能处理爆仓风险的密码**：如果你在锁定期内必须止损或追加保证金，这个工具会让你做不到。请保留独立的风险处理通道。

## 安全模型

- 密码由 `crypto.getRandomValues` 在本地生成，默认 24 位字母数字；
- 使用 [tlock-js](https://github.com/drand/tlock-js) 对明文做 AGE 加密，对称密钥再用 drand quicknet 的未来轮次公钥封装；
- 浏览器只存储密文、轮次、解锁时间和备注，不存储明文；
- 页面不发送任何数据到自有服务器；唯一的外部请求是读取 drand 公共信标；
- 备份 JSON 里同样只有密文。

## 已知问题

- 个别鸿蒙浏览器版本在“添加到桌面”后，首次打开可能白屏；刷新一次即可。
- 如果设备时间严重不准，页面会按本地时间倒计时；但真正的解密由 drand 轮次控制，提前点击只会得到 “too early”。
